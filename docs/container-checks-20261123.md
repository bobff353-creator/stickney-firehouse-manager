# Check items inside bags, kits and tool boxes

Active checks and the read-only member preview now show expandable container groups. Choose Show / hide contents to open the container's own check and the linked items that are on this checklist. Each item keeps its saved check ID, response format, result, quantity, notes and existing save handler. Saving a container does not pass any child. Original progress totals, pending blockers and submission/approval controls remain unchanged.

Grouping uses saved inventory parent IDs, never names. It requires the same rig and current compartment, and does not merge different original saved locations. Orphaned, moved, unknown and cyclic legacy links keep every check row reachable. A filtered-out container can still provide a group heading without inventing a check result. Empty groups explain that no contained items are listed on this checklist; grouping does not add new items to an existing saved inspection or bypass drug/meter validation.

Explicit child links also identify older containers whose item/grouping type was never recorded. These parents remain expandable and selectable in the location's container filter without rewriting their metadata. Names alone never create a grouping.

Native details controls keep child editors mounted when collapsed. Stable container keys retain child drafts when the parent result drops out of a Pending filter. Active grouping links are captured when that section opens, so a background inventory reassignment does not move a crew member's unsaved editor mid-entry. Opening a different check resets that presentation snapshot. Current previews remain read-only. Structured logging uses the crew theme palette in both preview and active check panels.

Local browser checks used only fictional transport: opening the group, keeping an unsaved mileage reading across collapse/reopen, preserving a medication note across collapse and parent save, passing the parent while two children stay pending, a child save failure/retry, saving each child independently, and all results ready for review only after every required row is saved. Preview expansion retained disabled controls. Phone/tablet/desktop widths 390/820/1388 and both themes were checked. No operational production result was used for testing.

Regression tests cover row/ID preservation, progress, filtering, stale/cyclic/foreign links, empty groups and duplicate legacy rows. The existing compact-start test harness was updated to register the location-filter module introduced in the previous release. Full inventory/security/fleet tests, TypeScript, changed-file ESLint, production build, exact release revision and read-only live verification are recorded in outputs/container-checks-20261123. No schema change or migration is required.
