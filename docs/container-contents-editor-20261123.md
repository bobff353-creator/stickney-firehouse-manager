# Container contents editor

Tool boxes, bags, kits and containers now show editable contents inside the existing item dialog, including empty containers. Administrators can rename a contained item, change its required quantity, add an existing individual item from the same saved compartment, create a new contained item, remove it from the container, or delete it from active inventory. Moves/removals/deletions have a named inline confirmation; deletion retains the existing history-preserving retirement behavior. Registered air equipment continues through its dedicated editor.

Membership and small item edits use a setup-permission API operation that changes only the requested fields. Queries are department-scoped, stale updates return a conflict, and conditional writes reject concurrent changes. Foreign, missing, retired, wrong-compartment and nested-container additions are rejected. Creation validates and assigns the parent before inserting the new item. No database migration, history rewrite, seeded operational records or notification change is included.

The parent dialog remains mounted while contents save. Its unsaved fields are retained. Changes use the container's saved location and save separately from its other fields; Refresh contents allows recovery after a conflict. The full asset editor remains available from the Equipment directory for additional service/checklist fields.

Validation: 217 focused Inventory/session/fleet tests passed, including actual API add/edit/remove/create, field and history preservation, tenant isolation, stale updates and denied/raced/failed writes. TypeScript, changed-file ESLint, production build and diff check passed. The local browser fixture exercised failed and retried edits, existing/new additions, removal, history-preserving deletion, and preservation of an unsaved parent name. Phone, tablet, desktop and both color schemes were checked. Production verification is read-only; no real container contents are changed as tests.
