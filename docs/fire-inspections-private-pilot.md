## Behavior and scope

- Work queue, dated calendar list, existing preplan property picker, optional contacts, occupancy, adopted code/edition and local amendments, custom/reusable checklists, six response choices, findings, notes, signature drawing, inspector review, private files, printable report and text report, archived records, audit versions.
- Schedule, reschedule, draft, in-progress, completion, and reopen-with-reason. Completion creates routine/reinspection follow-ups transactionally. Routine visits enter Needs scheduling. Failed items require an explicit reinspection decision: Schedule (date and time), Needs scheduling (with optional due date), or Not needed with reason. Recurrence is a selected department visit policy, never an inferred hood-service requirement.
- No copied licensed code database, automated compliance ruling, issued enforcement order, ESO integration, or push delivery. Due labels are shown in the private queue. A saved/downloaded report is not delivery confirmation.
- No real inspections or employee actions are generated by verification. Fixture records are local; any production smoke record must be clearly named test/inspection and marked test.
- API optimistic versions reject stale saves; an identical retry does not duplicate a report or follow-up. Save failures retain the client draft. Completed reports require a correction reason to reopen, which clears current signatures while preserving earlier audit versions.

## Signatures, codes, evidence, and email (September 25 update)

- Two drawn signature pads: representative receipt and inspector signature. Editing observations clears signatures and review acknowledgment. Saved signature timestamps are server generated. Exact retries preserve both timestamps.
- Deficiency photos attach to a saved checkpoint with a caption. Upload first saves progress without leaving Findings. Completed reports must be reopened before new evidence can be attached. A concurrent newer save prevents stale attachment metadata from committing.
- Code library supports Local ordinance, IBC, IFC, IEBC, NFPA, State rule, and Other. Search by text, code type, edition, and jurisdiction. Code text and applicability are owner-entered; no adopted requirements are invented. Each selection snapshots a versioned library entry. Editing or archiving the reference preserves older citations. PDF sources can be attached; their full text is not automatically indexed.
- Server-produced Letter-size PDF includes saved observations, both signatures, citations, photos and captions, and follow-up decisions. Original photos stay untouched; report copies are resized to bound memory and file size. Unsupported font characters cause a clear error instead of silently missing report text.
- Email is manually initiated after recipient review. Server uses RESEND_API_KEY and optional INSPECTION_EMAIL_FROM, otherwise the user-selected bwyant@stickneyfire.com sender. Sender-domain verification and real delivery must be tested separately from code tests. Do not claim successful sending just because a provider key exists.
- Each record/version/recipient has one immutable preserved PDF and provider idempotency key. Accepted differs from Delivered; network uncertainty is Unconfirmed. Manual status refresh avoids continual polling. Safe retries stop at 23 hours, before the provider's 24-hour idempotency expiry. Test reports only email the pilot owner.
- References: https://resend.com/docs/api-reference/emails/send-email and https://resend.com/docs/api-reference/emails/retrieve-email. Provider delivery is not a read receipt.
- Added tests cover code-edition search/history/tamper rejection, both signatures and retries, undated/scheduled reinspections, preserved PDF attachments, no duplicate send, uncertain response retries, owner-only email boundaries, and PDF rendering. All data in these tests is fictional.

- Unsaved inspection edits have a per-tab, department-keyed browser backup with a 24-hour expiry. Recovery retains the original saved version, so it cannot silently overwrite a newer record. A confirmed save or explicit discard clears the backup. This supplements manual saving; closing the tab removes session storage.
